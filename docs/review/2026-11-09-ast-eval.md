# The AST verbs' eval, 2026-11-09: two cases built to favour them

The question from 2026-10-01: the AST verbs (`clause move/split`, `rename`, `stmt`, `attr`,
`directive`, `module`, `block`) are kept but frozen until one eval built to favour them says keep or
cut. This is that eval.

## Setup

Suite `eval/ast` (one generated fixture, `gen_fixture.exs`), two cases, each one prompt:

- **rename-module**: `Acme.Billing` → `Acme.Invoicing` across the 53 files that name it in every
  spelling (alias, multi-alias, `as:`, import, struct, nested `Acme.Billing.Error`, typespec), file
  and test moved. Beside it, what a text rename hits and must not: `Acme.BillingAddress` (23 files),
  `Acme.Reports.Billing` behind its own `Billing` alias (8 files), the stored string
  `"Acme.Billing"`. The check: compiles with warnings as errors, suite and hidden test green, no
  `Acme.Billing` left outside the string, each collision on as many lines as at the base.
- **split-module**: the 1,817-line `Acme.Catalog` into five concern modules, 124 public functions
  with `@doc`/`@spec`, two private helpers shared across concerns, per-concern attributes, an alias
  and a `require`; the facade keeps only delegates; the 124 tests moved by `describe` into one file
  per concern. The check: every function in its module with its `@doc` and still on the facade
  (hidden test), no `def`/`defp` left in `catalog.ex`, no test lost, compiles clean, suite green.

Graders validated both ways before any run: menard's own `rename` (after the fix below) and a
reference split with `clause split` + `block move` pass; a sed rename over every `Acme.Billing`
(the string with it) and one over every bare `Billing` (the Reports alias with it) fail.

Arms, all on the same pinned menard (6cd4019):

- `none`: Claude Code alone.
- `ast`: the menard plugin as a user installs it: hooks, MCP tools, skill.
- `edit-only`: the same plugin copy with the AST verbs **denied** (`--disallowedTools` on the seven
  MCP tools and their `menard VERB` CLI forms) and the system prompt saying so. Chosen over a
  no-plugin arm because `none` already is one: `ast` against `edit-only` differs by the verbs
  alone, hooks, script refusal, `edit`, `outline`, `find` and `run` held equal.

Model claude-sonnet-5-5, 2 runs a cell, 12 runs. Results: `eval/results/2026-11-09-ast-rename`,
`eval/results/2026-11-09-ast-split` (runs.jsonl; traces kept locally). The machine sat at load
40-70 from other sessions throughout: wall times are soft, tokens are the measure.

## Numbers

Every run passed, and every run was clean (formatted, nothing outside lib/ and test/).
New in = uncached input + cache writes. Per run, run 1 / run 2:

| case | arm | new in | cached in | out | turns | wall s |
|---|---|---|---|---|---|---|
| rename | none | 21.1k / 20.3k | 85k / 54k | 1.9k / 1.7k | 4 / 3 | 64 / 58 |
| rename | edit-only | 20.2k / 26.0k | 57k / 124k | 2.0k / 4.3k | 4 / 5 | 47 / 93 |
| rename | ast | 27.6k / 26.9k | 124k / 122k | 1.0k / 1.0k | 5 / 6 | 56 / 48 |
| split | none | 27.2k / 26.8k | 192k / 225k | 5.3k / 4.9k | 7 / 9 | 101 / 110 |
| split | edit-only | 31.8k / 29.2k | 310k / 337k | 6.7k / 5.2k | 11 / 11 | 103 / 116 |
| split | ast | 40.6k / 41.0k | 425k / 665k | 6.0k / 8.0k | 20 / 25 | 140 / 163 |

What the `ast` arm reached for, unprompted (both runs alike):

- rename: `rename` once (MCP), after one ToolSearch to load it; 2-3 Bash calls (the `git mv`s,
  grep, the gate). No skill load.
- split: the skill, a ToolSearch, then `clause split` (the whole plan, one call), `clause move` for
  the two helpers the split left public in the facade, `block move` five times (one per describe),
  `outline` 0-2, `run check` 0-1, and 6-12 Bash calls.

How the others did it: `none` renamed with two `perl -pi` passes (a lookbehind keeping the string,
the bare `Billing` renamed only in files whose alias names `Acme.Billing`) and split with one Python
script over line ranges; `edit-only` renamed with two `sed -i` passes and, Python refused by the
hook, split with shell (`sed -n` ranges into heredocs). `edit-only` never tried a denied verb, so
the deny itself was not exercised.

## Reading

- **Correctness: a tie.** 12 of 12 pass, clean. Sonnet without menard is collision-aware with
  perl or sed on a 53-file rename and gets a 124-function split right with one script. The cases
  were built to be where text tools go wrong; on this model they did not.
- **rename: parity.** `ast` wrote least (1.0k out against 1.7-4.3k: one call instead of composing
  regexes) and paid ~6k more new input for the tool's schema (ToolSearch) and its reply. Turns and
  wall about even. The verb did what it claims in one call, but the call saved nothing a careful
  regex did not.
- **split: the verbs cost more.** `ast` against `none`: +50% new input, 2-3x cached input, +40%
  output, 2.5x turns. One `clause split` did the move, and then the agent spent 15 calls on what it
  left: the shared helpers published in the facade (moved again, their calls fixed by sed), the
  moved tests still calling `Acme.Catalog` (fixed by sed), and the plan's arities, which the agent
  computed with awk because a plan takes `name/arity` and not a pattern. A script that cuts line
  ranges does all of that in its one pass.
- **edit-only against none** shows menard's hooks-and-refusals cost on this work: more cached
  input on the split (1.4-1.8x), from doing in shell what Python would do in one script. It
  used menard's allowed verbs only lightly: `outline` 4 times, `run check` twice, `edit` once.

## Recommendation: keep some

On these numbers no AST verb earns its keep by tokens for a capable model, and none bought
correctness. Argued per verb:

- **Keep `rename`.** Parity in cost, least output, and it is the guarantee the text tools only
  meet by care: strings, comments and look-alike names untouched by construction. It is also the
  one verb an earlier round showed winning outright for a weaker model (bench6: haiku
  rename-across, 7 turns against ~20). It cost a fix to get here (below), so it stays tested.
- **Keep the readers** (`outline`, `clause get`, `find`): not under test here, used daily
  (transcript review 2026-11-08).
- **Cut, or leave frozen and off the skill's front page, `clause split`/`move` and `block move`**
  unless they finish the job in the one call: shared helpers to a module of their own rather than
  published in the facade, moved tests pointed at the new module, a plan by pattern. As they stand
  they cost 2.5x the turns of a script. If those three land, this case is the re-test.
- **Cut `stmt`, `attr`, `directive`, `module`.** Nothing in either case called them, the transcript
  review counted 0 calls in three weeks, and each is schema in every session that loads the tool.

Limits: one model (sonnet), 2 runs a cell, two cases. Haiku was not run; bench6 says a weaker
model is where `rename` pays. The operator leans keep: the case for keeping split/move is the
fixes above, not these numbers.

## menard bugs found building it (fixed, each test-first)

- `rename` of a module left the modules nested under it (`Acme.Billing.Error`, and `Billing.Error`
  after the alias) and a multi-alias entry (`alias Acme.{Billing, BillingAddress}`) untouched, so
  the project stopped compiling; and `alias X, as: Pay` was taken to bind `Billing` (b139128).
- A dev checkout's `bin/menard`, run from another directory, was answered by the installed
  plugin's hooks server through its door: the old build (05e5022).
- `clause split`/`move` carried a `require` to the new module and left it unused in the source,
  which fails `--warnings-as-errors` on Elixir 1.20 (09a4f1f).
- Open, in TODO.md: a multi-alias entry renamed to a name outside its base; alias binding decided
  per file, not per module.
