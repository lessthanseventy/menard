Every Elixir file written, by an edit or a shell command, is formatted after with the project's own formatter, and what it changed is said: there is no separate format step. There is no python, perl, ruby or node in this session: a command that runs one is refused. Text is replaced, in one file or many, in one call, with menard's `edit` tool (`mcp__plugin_menard_menard__edit`): `edits` is a list of `{file, old, new}`, every `old` found exactly once or nothing written, and an empty `old` makes a new file. A relative `file` is from the shell's directory. `then: "compile"` checks it builds, credo's findings on the lines changed beside it; `then: "test"`, on the last edit of a change, runs the tests of what it changed (mid-change, tests red for the change not yet made).
  {"edits": [{"file": "lib/a.ex", "old": "the text to find", "new": "the text to put there"},
             {"file": "lib/b.ex", "old": "…", "new": "…"}],
   "then": "compile"}
From the shell, the same edit is `menard edit --then compile - <<'EOF'`: each file's path on a line, then its `<<<<<<< SEARCH`, `=======`, `>>>>>>> REPLACE` blocks. What is no edit is the shell's: a wait or a loop in the shell itself (`until ! pgrep -f X >/dev/null; do sleep 2; done`), JSON with `jq`; past that, Elixir: `elixir -e '…'`, or `mix run -e '…'` for the project's own code.
For a module too big to read whole, when you want them: `menard outline FILE` lists every function and its lines, `menard clause get FILE NAME` reads one, `menard find calls Mod.fun DIRS` says who calls it.

Tests run with `menard run test [FILE[:LINE] …]`, and a change is finished on `menard run check` (format, warnings as errors, the whole suite): the answer is one JSON line, `ok`, the counts, and every failure with its file, line and message, a failed assertion with its left and right. Nothing is cut: read it whole, and never run again to see more. A `mix test` or `mix precommit` piped through tail, head or grep is run as these in its place. `menard …` itself runs bare: its reply piped into a filter that ends the line is run without it, and refused where more follows.
